本站首页有一段 Jojo 搭建页面的入场动画。最早我只在页面加载时检查了一次 `prefers-reduced-motion`，开了“减少动态效果”的用户第一次进来确实没看到动画，我就以为处理好了。后来才发现，这段动画还有别的入口：右下角 Jojo 的重放、URL 参数触发，而且真正开始前还要等字体和头像加载好。这些路径上都没人去问。

## 拆开看它怎么做到的

一段动画的入口往往不止一个，而 reduced-motion 的检查很容易只写在最显眼的那一个里。右边的做法：

```ts
async function guardedEntry(blocked, load, start) {
  if (blocked()) return false // 1. 出发前问一次
  const module = await load() // 等资源、等计时器、等动态 import……
  if (blocked()) return false // 2. 回来以后再问一次
  start(module)
  return true
}
```

- **所有入口都调用同一个守卫**。首次进入、重放、延迟自动播放，都走 `guardedEntry`，不在任何一个入口单独写判断。以后加了新入口，也不会漏。
- **跨过异步要再问一次**。中间隔着 `await`、`setTimeout` 或动态 `import()` 的，等回来的时候设置可能已经变了。被拦在第一道的话，连动画代码都不用加载。
- **播放途中也要听**。用 `matchMedia('(prefers-reduced-motion: reduce)')` 监听 `change` 事件，偏好一变就把正在播的动画 `finish()` 掉，直接跳到终点。用 `cancel()` 的话，元素会回到动画开始前的状态，内容可能就停在隐藏的样子了。

demo 里的反例只会忽略“模拟开关”。如果你的系统真的开了减少动态效果，两边都会遵守，我不想让一个讲无障碍的反例真的打扰到你。

## 什么时候不该用

- 减少动态效果不等于“什么都不变”。状态变化照样要发生，只是不播过程，直接到终点。
- 纯 CSS 的动画，一条 `@media (prefers-reduced-motion: reduce)` 就够了。需要这套守卫的，是 JS 驱动、有多个入口、或者会异步启动的动画。
