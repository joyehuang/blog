我在给本站做手绘风卡片时，想让几张卡片稍微歪一点，像随手贴在板子上。静态样式写了 `transform: rotate(-6deg)`，再给它们加一个从下往上浮起的入场动画。结果动画一播完，所有卡片整整齐齐全被摆正了，hover 上浮也失灵了。

## 拆开看它怎么做到的

问题出在两个细节叠加：

1. **动画和倾斜抢的是同一个属性**。关键帧写的是 `transform`，倾斜也写在 `transform` 里。动画运行时，关键帧的值直接覆盖元素自己的 `transform`，而不是叠加上去。
2. **`forwards` 让动画一直不退场**。`animation-fill-mode: forwards` 会在动画结束后继续保留最后一帧。最后一帧是 `transform: none`，于是动画层永远在说“transform 是 none”，倾斜没了，`:hover` 里写的 transform 也被压在下面。

右边的改法也是两步：

```css
.note {
  rotate: var(--rot); /* 倾斜放到独立的 rotate 属性 */
  animation: drop 0.7s ease-out backwards;
  animation-delay: calc(var(--i) * 90ms);
}
@keyframes drop {
  from {
    opacity: 0;
    translate: 0 24px;
  } /* 只写 from，终点就是元素自己的样式 */
}
.note:hover {
  translate: 0 -6px;
}
```

- `rotate`、`translate`、`scale` 是三个独立的 CSS 属性，和 `transform` 互不覆盖。入场只动 `translate`，动画根本碰不到角度。
- `backwards` 只在动画**开始之前**（也就是错开的 delay 里）先套用第一帧，让卡片提前藏好；播完就把属性还给元素，hover 能正常生效。
- 关键帧只写 `from`，终点自动就是元素本身的样式，不用把角度在关键帧里再抄一遍。

## 什么时候不该用

- 动画确实需要停在一个跟静态样式不同的终点时，`forwards` 是对的。这时候我会让外层元素负责入场、内层负责倾斜，或者动画结束后把终点写回静态样式，而不是一直靠 `forwards` 撑着。
- 独立变换属性在现代浏览器里都能用（Chrome 104+、Safari 14.1+、Firefox 72+）。要兼容更老的环境，就用外层 / 内层两个元素拆开。
- 系统开启减少动态效果时，demo 里两边都不播入场，便利贴直接以倾斜的样子出现。

## 出处

来自我给本站手绘风样式踩的坑，demo 是重新搭的。独立变换属性的说明见 [MDN: rotate](https://developer.mozilla.org/en-US/docs/Web/CSS/rotate)，`forwards` / `backwards` 的行为见 [MDN: animation-fill-mode](https://developer.mozilla.org/en-US/docs/Web/CSS/animation-fill-mode)。
