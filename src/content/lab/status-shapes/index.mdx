任务列表、部署记录、Agent 的执行日志里，最常见的状态标记就是一个彩色小圆点：绿的完成、红的失败、黄的进行中。设计稿里看着很清爽，可一旦换一双眼睛（色弱）、换一块屏幕（灰度、强光下的手机），或者把图标缩得再小一点，这套信号就读不出来了。

## 拆开看它怎么做到的

右边给四种状态各配了一个**轮廓完全不同**的形状：

| 状态     | 形状             | 为什么这么选                       |
| -------- | ---------------- | ---------------------------------- |
| 运行中   | 开口的弧，会转   | 唯一“没闭合”的形状，动起来也最显眼 |
| 等你确认 | 带尾巴的对话气泡 | 有尾巴，和圆、三角都不像           |
| 完成     | 实心圆 + 对勾    | 最“安定”的形状，完成了就该安静     |
| 失败     | 三角 + 感叹号    | 警告三角在交通标志里就有固定含义   |

- **先挑轮廓，再挑颜色**。缩到很小时，先糊掉的是里面的对勾和感叹号，外轮廓（弧 / 气泡 / 圆 / 三角）还分得开。可以点“缩小图标”试试。
- **颜色保留，但不再单独承担意思**。色弱模拟下颜色全变了，右边照样能读，左边只能挨个对图例。
- **图标要带文字**。每个图标都有 `aria-label`，屏幕阅读器读的是“失败”，而不是一个看不见的形状。
- 运行中的弧会一直转；系统开启减少动态效果时，它停成一段静止的弧，形状本身仍然能说明状态。

“红绿色弱模拟”用的是 SVG `feColorMatrix`，矩阵来自 Machado 等人 2009 年的色觉缺陷模型，只是近似效果，但足够说明问题。

## 什么时候不该用

- 状态只有两种、旁边又有文字（比如“已发布 / 草稿”标签），文字本身就够了，不必硬配图标。
- 状态种类太多时，形状也会不够用。超过五六种，就该老老实实写文字，而不是发明一套没人记得住的图标语言。

## 出处

依据是 WCAG 的 [1.4.1 Use of Color](https://www.w3.org/WAI/WCAG22/Understanding/use-of-color.html)：颜色不能是传达信息的唯一方式。这几种形状的选择，来自我给 Jojo 设计状态信号（工作中、等你输入、完成）时的思路；demo 用的是新画的几何图形，没有用角色素材。
